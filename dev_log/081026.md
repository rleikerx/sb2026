# 10 Aug 2026 — the creature export must ship the rest pose for Aegisfall

Written from the Aegisfall side, because the effect landed there and the cause is here.

## What happened

`stand_pose` went into the creature export on 9 Aug and all 2,380 creatures were regenerated with
it. Aegisfall stages its character pack out of `export_aegisfall/models/Creature`, and the next time
it did so, the worst joint gap in its body-assembly gate went from **4.6 cm to 15.9 cm** — knees on
the Dwarf, the Elf, the Aelfborn, the Centaur and both Half-Giants.

Nothing failed at export time or at staging time. It surfaced two steps downstream as a gate nobody
would connect to an export, and it looked for a while like Aegisfall's own staging tool had
regressed.

## Why a stance breaks that consumer specifically

Aegisfall does not draw the export's pose. It re-poses everything itself: its loader bakes
`inverse(rest[part])` into each staged part so that its own placement and its own pose cancel
*exactly at rest*, and then stretches each limb to span the rig's segment lengths. A stance already
baked into the vertices breaks that cancellation, and the error scales with each bone's distance
from the origin.

Measured on one body, before and after, as a best-fit transform per part:

```
  every part rigidly rotated, a DIFFERENT amount each   det 1.000, residual 1e-7
  magnitude grows down the bone chain                   root 4.98deg -> head 32.7 -> foot 90.16
  BEARD and HAIR carry HEAD's transform                 bit-for-bit identical
  the merged HAND is the only non-rigid node            four bones, each rotated separately
  left/right symmetry on centre-line parts              bit-exact before, destroyed after
```

That last row is a nice property of the rest pose and worth knowing: at rest these bodies are
symmetric about `x = 0` to the last bit on the merged centre-line parts.

The foot's **90.155°** is worth flagging on its own — that is `stand_pose` standing the foot up from
the cache's toes-down bind, which is the same correction Aegisfall's loader applies. Both pipelines
were doing that one job, and doing it twice put every character's feet vertical.

## What was done

Re-exported all creatures with the flag that already existed:

```bash
python tools/export_assets.py --kind Creature --all --rest-pose \
  --out export_aegisfall/models --format glb
```

44 seconds, 2,380 exported, 315 with no geometry, 0 failed. `merge_manifest` carried the other 7,544
rows, so the manifest is still 9,924.

**Verified by byte-identity, not by eye:** Aegisfall's `assets:bodies` now reproduces its committed
pack exactly — 104 bodies, 54.37 MB, zero files differing — and its assembly gate is back to 4.6 cm.
So its committed pack was never stale; it was the last one staged from rest-pose art.

## What this asks of the exporter

**`export_aegisfall/models/Creature` should stay rest pose.** It is the handoff bundle for a consumer
that animates everything itself, so the stance is not just unnecessary there, it is destructive.

If the standing pose is wanted for the viewer or the pose sheet, it wants its own output directory
rather than this one — `--out` already makes that a one-word change, and the two can coexist.

`stand_pose` itself is not in question. The work on it (the upright gate reading six frames instead
of one, the hunched rung, the wing folds) is good and none of it is undone by exporting this bundle
at rest.

## Still open

Aegisfall tried to add a guard that refuses to stage a posed export, keyed on that bit-exact
symmetry. It **fired on good data** — the symmetry is exact on the *staged, merged* parts, not on raw
export nodes, where even a correct head reads 1.45 mm out. With the posed export overwritten there is
no bad sample left to calibrate a threshold against, so the guard was removed rather than tuned to a
number nobody could defend.

So this can recur silently. Until there is a guard, the rule on the Aegisfall side is: after any
export refresh, run `assets:bodies` and then `bodyAssembly.test.ts` before trusting the pack.
